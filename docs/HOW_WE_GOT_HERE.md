# How we got here

## Step 1: skeleton page (v0.1.0)

- The core is one package, `Hood.Host_ABI`, with integer-only exports: `hs_build_id`, `hs_state_hash`, `hs_crash_test`, `hs_error_file_length`, `hs_error_file_char`. The host provides one import, `hs_host_error (code, line)`.
- The browser runtime of AdaWebPack has no exception propagation and the wasm build uses `-gnatp`, so a stop is an explicit `raise`. GNAT turns it into a call of `__gnat_last_chance_handler (file, line)`. `src/wasm/hood-last_chance.adb` replaces that handler in the browser build only: it keeps the Ada file name, then calls `hs_host_error` with the pending code and the line. The host reads the file name one character at a time through `hs_error_file_char`, so the interface stays integer-only.
- The native smoke build uses the normal GNAT runtime, so the same `raise` becomes `Program_Error` with the message `file:line explicit raise`; the smoke test prints it, and the page must show the same file and line.
- `hs_state_hash` is a placeholder until the world exists: FNV-1a (32 bit) over the four bytes of seed 1932. The smoke test recomputes it independently.
- `hs_build_id` is the build time as `YYDDDHHMM` (Europe/Berlin), so it fits in 32 bits; `build.sh` writes it, with the stamp, into the generated `obj/gen/hood-version.ads`.
- New constants (all proposed): version 0.1.0; build id format `YYDDDHHMM`; error codes 1 bounds, 2 range, 3 unexpected state, 4 crash test; hash seed 1932; 1 MiB stack; 32 MiB initial memory.

## Step 2: random numbers, whole-number positions, table trigonometry and the grid (v0.2.0)

- **Random numbers (`Hood.Random`).** 1.2.91 draws all simulation randomness from mulberry32 (`src/sim/rng.ts:6-29`, one 32-bit state, seed 0 replaced by 0x9E3779B9). The city-plan generator uses a second generator, an LCG `s := s × 214013 + 2531011` returning 15 bits, and `hash32` (`src/sim/hash.ts:8-13`) is a third. All three are integer arithmetic modulo 2^32, so Ada reproduces them bit for bit. The TypeScript helpers that divide by 2^32 (`int`, `pick`, `shuffle`, `weighted`, `chance`) become exact integer formulas such as `(u × span) >> 32`; they agree with the TypeScript results as long as a span or weight total stays below 2^21, which the contracts require. `chance` takes a fraction (`35/100`).
- **Streams.** The simulation stream starts from the city seed (`citygen.ts:362`); the city plan from the city seed plus a retry count; headquarters placement from the city seed xor 0x5EED0400; rivals from `seed + week × 997 + gang id × 13` (`rivalPlaybook.ts:38`; gang id numbering is item 9); Auto from `auto seed + week × 997` (`autoTest.ts:1178`), `+ runs × 9973` (`strategy.ts:205`) and `(seed xor 0x5EED) + week × 7919` (`autoLearn.ts:47-48`).
- **Reference values.** `rng.ts` was run unmodified in Node for seed 1932. The page and the native smoke test each hold their own typed copy of the values: the first 20 of mulberry32, of `int(0, 99)` and of the city-plan LCG (shown on the page), plus the headquarters and Auto week-1 streams, `chance`, `pick`, `shuffle`, `weighted`, three more stream seeds and `hash32` (smoke only). All match.
- **Whole numbers, not Ada fixed point (`Hood.Units`).** The browser runtime has no `s-arit64`, and the build links only three runtime objects, so products of an Ada fixed-point type would not link. `Units` is a 32-bit whole number counting 1/256 of a 1.2.91 unit; products go through `Integer_64` and divisions round down. The Large city's widest coordinate is 2,376 × 256 = 608,256, whose square needs 64 bits, so `Isqrt` works on `Unsigned_64` with the contract r² ≤ n < (r + 1)².
- **Table trigonometry (`Hood.Trig`).** Angles are `mod 1024`. `tools/gen-trig.py` writes the 257-entry quarter-wave table `src/hood-trig_table.ads` (sine × 65,536, rounded). `Atan2` reduces to the first octant and bisects the table, so it is within one step of the exact angle; over all 1,024 angles the round trip `Atan2 (Sin, Cos)` returns the same angle, and `sin² + cos²` is within 73,584 / 2^32 of 1 (bound from rounding: 92,683).
- **The grid (`Hood.Grid`).** A cell is 54 / 5 = 10.8 units; a position's cell is `x × 5 / 13,824` rounded down, so the cell size never has to be a whole number. The street runs 7 units either side of each block line, so of a block's five cells the middle three are block (cell centres 16.2, 27 and 37.8 lie between 7 and 47) and the first and last are street. The Large city is 44 × 35 blocks = 220 × 175 = 38,500 cells.
- **World and hash (`Hood.World`).** The world holds the seeds, size, both stream states, week, minute and the grid. `hs_state_hash` is FNV-1a over those fields in the order written in `src/hood-world.ads`, four little-endian bytes each, then each cell inside the city row by row. For seed 1932 / Auto seed 1932, Large: 0xD7F87E73. 1.2.91 has no world hash, so this compares the native and browser builds only.
- **No elaboration in the browser.** The browser build has no binder, so library-level initial values that need code never run. `hs_new_game` sets every field of the world, and every export returns 0 or −1 until it has run.
- **New exports:** `hs_new_game (seed, auto_seed, w, h)`, `hs_rng_value (stream, index)`, `hs_grid_w`, `hs_grid_h`, `hs_cell_kind (x, y)`, `hs_check_value (id)`.
- **New constants (all proposed):** version 0.2.0; 1,024 angle steps; sine × 65,536; 257-entry table; floor rounding; cell kinds 0 street, 1 block; hash field order; stream numbers 1 mulberry32, 2 int(0, 99), 3 city-plan LCG; check ids 1–9; weight limits 1,024 items below 2,048 each.

## Step 3: city generation in the placeholder street view (v0.3.0)

- **Data.** `data/tables.json` holds the 1.2.91 data tables (`src/sim/data/`: building types, business kinds, trades, block modules and module families, park, church and street names). `tools/gen-tables.py` turns it into `src/hood-tables.ads` (Ada) and `web/src/tables.ts` (the names the page shows). Both generated files are committed.
- **Two city paths, as in 1.2.91.** The Standard city (40 × 32) is built from the city-plan generator (`Hood.City.Plan`, LCG stream 3): blocks, parks and church merges, civic lots, tenements, house runs, firms, empty and soup kitchen lots (`Hood.City.Standard`). Every other size goes through the varied layout (`Hood.City.Varied`): districts, reserved civic places, block modules and their lots, trade and type picks per lot. Both paths draw from the simulation stream in the same order as 1.2.91, so the stream state after the city matches.
- **Exact districts.** The varied path's district test compares squared distances as whole numbers, `10000 (a² + b²) < t (w h)²` with t = 784, 1,764, 5,184, so no square root is needed. 64 cells lie exactly on a boundary (all on an axis, on sizes with a side of 25); 1.2.91 also puts them outside, which the strict `<` reproduces.
- **Headquarters (Standard only).** The four gangs' headquarters blocks come from the headquarters stream (city seed xor 0x5EED0400) over a 200 × 160 fine grid (5 × 5 cells per block): a centroid per gang, a jitter, a square spiral to the nearest unclaimed business or tenement cell, then one attitude draw per owned building cell within reach (the exact `dx² + dy² < 55²`: 11 bands of 480 units at 96 units a cell, `attitudes.ts:92-93, :112-114`). The Large and Small cities' headquarters follow in step 4.
- **Two hashes (proposed, `src/hood-city.ads:122-133`).** Both are FNV-1a with four little-endian bytes per value, taken where 1.2.91 starts placing people (`citygen.ts:539`), before the headquarters. `hs_city_hash` covers every block (position, district, land value, squalor, use, spans, merge), every lot (block, index, centre position, its building) and every building (lot, block, type). `hs_structure_hash` is the same without positions and spans, so it shows whether a difference is only geometry. The same two sums were computed over 1.2.91's city in Node. The world hash (`hs_state_hash`) now also takes the city hash, so its step 2 value changes: Standard 1932 0x3724FC3B, Large 1932 0xDE0B89B3.

- **Caps measured.** Largest counts seen: 1,540 blocks, 13,488 lots (Large 1932), at most 17 lots in one block (Small and Large). The caps stay 1,540 blocks and 18,480 lots and buildings.
- **Exports.** `hs_count (id)`, `hs_get (table, index, field)`, `hs_draw_ptr (layer)`, `hs_draw_len (layer)`, `hs_city_hash`, `hs_structure_hash`. The draw layers are whole-number arrays in wasm memory: layer 1 blocks (12 numbers each: gx, gy, district, use, span x, span y, merged into, land value, squalor, content, rail, landmark), layer 2 lots (10 numbers each: block, index, x, y, w, h, face, type, class, storeys; positions in 1/256 m). `tests/wasm-check.mjs` checks in Node that the layers hold the same numbers as `hs_get`.
- **The page.** The view is new TypeScript (Vite, React 18.3.1, Three.js 0.169.0; React, ReactDOM and Three.js are sibling files in `dist/vendor/`, each loaded with the build stamp in its URL). The street view draws blocks as slabs and buildings as boxes, with the 1.2.91 camera (orthographic, 30° elevation, zoom 0.55–11, drag, wheel, pinch, arrow keys, turn). The city plan draws the whole city flat with a flag per headquarters. Clicking a building in either view opens its card. Panels that later steps fill are shown disabled with their step number. The Debug drawer shows the step 3 matches above the step 1 and 2 checks. New game asks for a seed and Small, Standard or Large; the default is 1932, Standard.
- **New constants (all proposed):** version 0.3.0; count ids 1–9, 10 + class, 20 + district, 30 + use, 40 types used, 41 industrial edge, 42/43 stream state low/high 16 bits; tables 1 block, 2 lot, 3 building, 4 headquarters and their field numbers (`src/hood-host_abi.ads`); draw layers 1 blocks (stride 12) and 2 lots (stride 10); name numbers Volstead 0, Hinge 1, Cinder 3, churches 0 and 1; Standard lots face south; storey height 4.2 m; class and gang colours (`web/src/street/scene.ts`).
- **Not yet:** trams (step 6), the Large and Small headquarters (step 4), the inspect card, people.
